# راه‌اندازیِ اعلانِ گوشی با Firebase — گام‌به‌گام برای صاحب‌کار

**هدف:** وقتی برنامهٔ اندرویدِ دکان **بسته** است، سفارشِ آنلاینِ تازه (و پرداخت یا لغوِ مشتری) روی گوشی زنگ بزند —
همان کاری که برنامه‌های بزرگ می‌کنند. تصمیمش گرفته شد (O-01 در `docs/OWNER-DECISIONS-fa.md`).

**همه‌چیز در کد آماده است و خاموش.** بی کارهای زیر هیچ چیزی عوض نمی‌شود: برنامه و سرور مثلِ امروز کار می‌کنند و
سفارش فقط وقتی برنامه باز است خبر می‌دهد. فقط **شما** می‌توانید این چند کار را بکنید، چون حسابِ گوگل مالِ شماست.

زمانِ لازم: حدودِ ۲۰ دقیقه. هزینه: **رایگان** (طرحِ رایگانِ Firebase به نامِ Spark؛ اعلان در آن رایگان و بی‌سقف است).

فایلِ اول فقط در «Secrets» و فایلِ دوم فقط روی کامپیوترِ سرور.

## گامِ ۱ — ساختنِ پروژهٔ رایگانِ Firebase

1. با **حسابِ گوگلِ خودتان** (همان که می‌خواهید مالکِ پروژه بماند) به نشانیِ <https://console.firebase.google.com> بروید.
2. «**Create a project**» (یا «Add project») را بزنید.
3. نامِ پروژه: مثلاً `vill3n` (هر نامی؛ فقط برای خودتان است). ادامه.
4. صفحهٔ «Google Analytics» را **خاموش** کنید — لازم نیست و داده‌ای هم از برنامه به آن نمی‌رود. «Create project».
5. چند ثانیه صبر کنید تا «Your new project is ready» و «Continue».

طرحِ پروژه همان **Spark (رایگان)** است؛ هیچ کارتِ بانکی‌ای لازم نیست. اگر روزی پرسید «ارتقا بدهید»، برای اعلان لازم نیست.

## گامِ ۲ — افزودنِ برنامهٔ اندروید و گرفتنِ `google-services.json`

نامِ بستهٔ برنامه (همان که در `android-native/app/build.gradle.kts` نوشته شده): **`ir.vil3ntec.tohid`**.
نسخهٔ «پیش‌نمایش» بستهٔ جدای **`ir.vil3ntec.tohid.preview`** دارد. **هر دو** را بیفزایید:

1. در صفحهٔ اولِ پروژه، نشانِ اندروید (آدمکِ سبز) یا «**Add app**» ← «Android».
2. «Android package name»: دقیقاً `ir.vil3ntec.tohid` (بی فاصله، با حروفِ کوچک). «App nickname»: `توحید`.
   «Debug signing certificate SHA-1» را **خالی** بگذارید (برای اعلان لازم نیست). «Register app».
3. دکمهٔ «Download google-services.json» را فعلاً نزنید؛ «Next»، «Next»، «Continue to console».
4. دوباره «Add app» ← «Android»، این بار نامِ بسته `ir.vil3ntec.tohid.preview` و نام `توحید — پیش‌نمایش`. «Register app»، بعد تا آخر «Next».
5. حالا از چرخ‌دندهٔ بالای چپ ← «**Project settings**» ← زبانهٔ «General»، پایینِ صفحه در «Your apps» یکی از دو برنامهٔ اندروید را
   بزنید و «**google-services.json**» را دانلود کنید. این فایل **هر دو** برنامه را دارد (چون پس از افزودنِ هر دو گرفته شد).

اگر فایل را پیش از افزودنِ برنامهٔ دوم گرفته باشید، فقط یکی را دارد: ساختِ پیش‌نمایش بی اعلان می‌ماند و در CI یک هشدار
می‌بینید («google-services.json برنامهٔ … را ندارد»). کافی است فایل را دوباره بگیرید و گامِ ۳ را تکرار کنید.

## گامِ ۳ — گذاشتنِ فایل در GitHub (برای ساختنِ برنامه)

1. در GitHub به مخزنِ `vil3ntec-it/shop` بروید ← «**Settings**» ← «**Secrets and variables**» ← «**Actions**».
2. «**New repository secret**».
3. Name: دقیقاً **`GOOGLE_SERVICES_JSON`**
4. Secret: فایلِ `google-services.json` را با یک ویرایشگرِ متن (Notepad) باز کنید، **همهٔ** متنش را کپی و این‌جا بچسبانید.
   (اگر ترجیح می‌دهید، نسخهٔ base64 ِ فایل هم پذیرفته است.) «Add secret».

از این لحظه هر ساختِ تازهٔ برنامه (`توحید بومی` و `پیش‌نمایش` در Actions) اعلانِ گوشی را دارد. ساختِ بعدی با هر کامیتِ تازه
روی `main` خودش انجام می‌شود؛ برای ساختِ فوری: «Actions» ← «توحید بومی» ← «Run workflow».

- بی این secret هیچ ساختی نمی‌شکند؛ فقط برنامه بی اعلانِ گوشی ساخته می‌شود (در گزارشِ ساخت یک «notice»).
- این فایل رازِ سنگینی نیست (درونِ هر APK هست)، ولی جای درستش همین Secrets است، نه مخزن.
- برای ساختِ برنامه روی کامپیوترِ خودتان: فایل را در `android-native/app/google-services.json` بگذارید؛ git آن را نمی‌بیند.

## گامِ ۴ — کلیدِ حسابِ سرویس برای سرور

این **راز** است: هر کس آن را داشته باشد می‌تواند به گوشی‌های شما اعلان بفرستد. فقط روی کامپیوترِ سرور بماند.

1. در کنسولِ Firebase: چرخ‌دنده ← «Project settings» ← زبانهٔ «**Service accounts**».
2. «Firebase Admin SDK» انتخاب‌شده باشد ← «**Generate new private key**» ← «Generate key».
   فایلی مثلِ `vill3n-firebase-adminsdk-xxxxx-1234567890.json` دانلود می‌شود.
3. در زبانهٔ «**Cloud Messaging**» همان صفحه، سطرِ «Firebase Cloud Messaging API (V1)» باید «**Enabled**» باشد
   (در پروژهٔ تازه خودش روشن است). اگر «Disabled» بود، روی سه‌نقطه ← «Manage API in Google Cloud Console» ← «Enable».
4. روی **کامپیوترِ سرورِ خانگی** (همان‌جا که سرورِ دکان با `docker compose` بالاست):
   - در پوشهٔ `server` ِ همین مخزن، پوشهٔ `secrets` را بسازید (اگر نیست) و فایل را با نامِ
     **`fcm-service-account.json`** در آن بگذارید: `server/secrets/fcm-service-account.json`.
     (git این پوشه را نمی‌بیند و درونِ image ِ Docker هم نمی‌رود.)
   - دسترسی: `chmod 644 server/secrets/fcm-service-account.json` (سرور درونِ container با کاربرِ `node` می‌خواندش؛ خودِ
     کامپیوترِ سرور را به کسِ دیگری ندهید).
   - در فایلِ **`server/.env`** این سطر را بیفزایید (همین مسیر، چون این مسیرِ **درونِ** container است):

     ```
     FCM_SERVICE_ACCOUNT_FILE=/app/secrets/fcm-service-account.json
     ```

   - سرور را دوباره بالا بیاورید: در پوشهٔ `server`، `docker compose up -d`.
5. فایلِ دانلودشده را از پوشهٔ «Downloads» ِ کامپیوترِ خودتان پاک کنید (یک نسخه روی سرور بس است).

راه‌های دیگر (اگر بی Docker اجرا می‌کنید): متغیرِ محیطِ `FCM_SERVICE_ACCOUNT_FILE` با مسیرِ واقعیِ فایل، یا
`FCM_SERVICE_ACCOUNT` با خودِ متنِ JSON. پنلِ مدیر («ایمیل و پوش» ← «فایلِ حساب سرویس») هم کلید را می‌پذیرد، ولی آن‌جا کلید
در پایگاه‌داده و در پشتیبان‌ها می‌نشیند — **فایل پیشنهاد می‌شود.**

**اگر کلید لو رفت:** همان «Service accounts» ← «Manage service account permissions» (Google Cloud) ← حساب ← «Keys» ← کلیدِ
کهنه را **Delete** کنید، کلیدِ تازه بسازید و گامِ ۴ را تکرار کنید.

## گامِ ۵ — روشن کردن

سه کلید، همه پیش‌فرض خاموش. اول فقط برای **یک دکانِ آزمایشی** روشن کنید.

1. **کلیدِ اصلیِ پوش ِ سرور** — پنلِ مدیر (`https://api.vill3n.top/admin/`) ← زبانهٔ «**ایمیل و پوش**» ← بخشِ «پوش» ←
   تیکِ «**روشن**» ← «ذخیره». کنارِ عنوان باید «✅ روشن · … دستگاه · نامِ پروژهٔ شما» بیاید (کلید از فایلِ گامِ ۴ خوانده شد؛
   «فایلِ حساب سرویس داده نشده» یعنی گامِ ۴ هنوز به سرور نرسیده).
2. **پرچم‌های دکان** (پنلِ مرکزی ← «پرچم‌ها و تنظیماتِ زنده»؛ scope = **شناسهٔ دکانِ آزمایشی**، بعداً `all`):
   - `shop.device_push` = `true` — برنامهٔ گوشی Firebase را روشن و توکنِ دستگاه را ثبت می‌کند.
   - `shop.order_notify` = `true` — سرور برای سفارشِ تازه، پرداخت و لغوِ مشتری اعلان می‌فرستد (و تا کسی باز نکرده دو بار یادآوری).

   اگر پنل این دو را در فهرست نشان نداد، همان کار با API (توکنِ مدیرِ ارشد؛ دلیل اجباری است):

   ```
   curl -X PUT https://api.vill3n.top/api/admin/flags \
     -H "Authorization: Bearer <توکنِ مدیر>" -H "Content-Type: application/json" \
     -d '{"scope":"<شناسهٔ دکان>","key":"shop.device_push","value":true,"reason":"آزمونِ اعلانِ گوشی"}'
   ```

   (همین را با `"key":"shop.order_notify"` هم بزنید.)
3. **برنامه** — نسخه‌ای که **پس از** گامِ ۳ ساخته شده را روی گوشی نصب کنید (به‌روزرسانیِ درونِ برنامه یا پیش‌نمایش).

خاموش کردن، هر وقت: همان پرچم‌ها `false`. با `shop.device_push = false` برنامه توکنِ خودش را باطل می‌کند؛ با کلیدِ «روشن» ِ
پنل خاموش، سرور هیچ اعلانی نمی‌فرستد (یک بار در لاگ می‌گوید چرا).

## گامِ ۶ — آزمون با یک گوشیِ واقعی

1. در گوشی وارد حسابِ دکانِ آزمایشی شوید. اگر پرسید «اجازهٔ اعلان»، **اجازه** بدهید.
2. «تنظیمات» ← «فروش و پرداخت» ← «**سفارشِ آنلاین**». باید ببینید:
   «اعلانِ گوشی روشن است: برنامه بسته هم باشد، سفارشِ تازه، پرداخت و لغوِ مشتری خبر داده می‌شود.»
   اگر نوشتهٔ دیگری بود، جدولِ «عیب‌یابی» پایین را ببینید.
3. برنامه را **ببندید** (از فهرستِ برنامه‌های اخیر کنار بکشید). ⚠️ از «تنظیماتِ اندروید ← Force stop» استفاده نکنید:
   اندروید به برنامه‌ای که دستی «متوقف» شده هیچ اعلانی نمی‌دهد تا دوباره باز شود — این قاعدهٔ خودِ اندروید است.
4. با گوشی یا کامپیوترِ دیگری از ویترینِ همان دکان یک سفارش بدهید.
5. در چند ثانیه روی گوشیِ دکان: «**سفارشِ تازه — شمارهٔ …**». متنِ اعلان **هیچ** نام، شماره، نشانی یا مبلغی از مشتری ندارد
   (صفحهٔ قفلِ گوشی جای آن نیست)؛ با لمسش برنامه باز می‌شود و همان سفارش را از سرور می‌خواند.
6. اگر کسی باز نکند، پس از حدودِ دو دقیقه یادآوری می‌آید (حداکثر دو بار).
7. همین را برای «پرداخت شد» (پرداختِ آنلاین) و «مشتری سفارش را لغو کرد» هم ببینید. نتیجه را برای ثبت در
   `docs/spec/STATUS.md` (ردیف‌های NOTIF-02 تا NOTIF-05، NOTIF-12، NTF-05، ORD-02 و S36) به Claude بگویید.

## عیب‌یابی — صفحهٔ «سفارشِ آنلاین» چه می‌گوید

| نوشته | یعنی | چه باید کرد |
|---|---|---|
| «این نسخهٔ برنامه هنوز به سرویسِ اعلانِ گوشی (Firebase) وصل نیست» | APK بی `google-services.json` ساخته شده | گامِ ۳، سپس نسخهٔ تازه |
| «اعلانِ گوشی با برنامهٔ بسته برای این دکان هنوز روشن نشده» | پرچمِ `shop.device_push` خاموش | گامِ ۵، بندِ ۲ |
| «این گوشی ثبت شد، ولی سرور هنوز … آماده نیست» | کلیدِ «روشن» ِ پنل یا فایلِ گامِ ۴ نیست | گامِ ۴ و گامِ ۵، بندِ ۱؛ لاگِ سرور یک خطِ `[push] …` دارد |
| «این گوشی برای اعلان ثبت نشد» | گوشی «خدماتِ Google Play» ندارد/خاموش است، یا نت نبود | Google Play Services را روشن/به‌روز کنید؛ صفحه را دوباره باز کنید |
| «اجازهٔ اعلانِ این برنامه بسته است» + دکمهٔ «اجازهٔ اعلان» | اجازهٔ اعلانِ اندروید داده نشده | دکمه را بزنید؛ اگر اندروید دیگر نپرسید، تنظیماتِ اعلانِ برنامه باز می‌شود |
| «سفارشِ تازه فقط وقتی این برنامه باز است خبر می‌دهد…» (و نوشتهٔ دیگری نیست) | هنوز وارد نشده‌اید یا نت نیست | وارد شوید، نت را وصل کنید و صفحه را دوباره باز کنید |

اعلان رسید ولی زنگ نزد ⇒ در تنظیماتِ اعلانِ گوشی برای این برنامه، کانالِ «سفارش‌های آنلاین» را روی «صدا» بگذارید.

## آیفون

اعلانِ آیفون از راهِ Firebase نمی‌رود؛ با سرویسِ خودِ اپل (APNs) است و حسابِ **Apple Developer** (پولی) می‌خواهد — تصمیمِ
O-02. کد برای آن روز آماده است (`ios/shared/.../IosPush.kt` و `server/src/lib/apns.js`، `docs/IOS-PLAN-fa.md` §۰.۶ و §۰.۱۰)؛
تا آن روز آیفون فقط وقتی برنامه باز است خبر می‌دهد.

## برای برنامه‌نویس (کجا چیست)

- سرور: `server/src/lib/push.js` (FCM HTTP v1؛ کلید از `FCM_SERVICE_ACCOUNT_FILE` یا `FCM_SERVICE_ACCOUNT`؛ بی کلید یک بار لاگ و
  هیچ)، `server/src/routes/shop-push.js` (`/api/shop/push/config|devices`، پرچمِ `shop.device_push`)، `server/src/lib/order-notify.js`
  (سفارشِ تازه/پرداخت/لغو، پرچمِ `shop.order_notify`)، مهاجرتِ `213_device_push.sql`؛ آزمون: `server/test/push-fcm.test.js`.
- اندروید: `data/push/DevicePushAndroid.kt` (مشترک)، `data/push/FcmPushAndroid.kt` (فقط اندروید)، `core/push/PushPolicy.kt` (خالص)،
  افزونهٔ google-services فقط با `app/google-services.json` (`android-native/app/build.gradle.kts`)؛ CI: `android-native/tools/google-services.sh`.
- قاعده‌ها: `docs/RULES-fa.md` ← «v3 · اعلان».
