# `vill3n-sdk.js` — یک فایل، همهٔ کارِ سرور

> بخشِ ۱۳.۳ی پرامپت: «یک SDK کوچک به برنامه اضافه می‌شود که همه‌چیز را یکجا
> می‌دهد: ورود با کد ایمیلی، بررسی لایسنس، Heartbeat، Sync اختیاری، بخش
> پشتیبانی، دریافت آپدیت، ارسال خطاها.»

## چرا هست

هر برنامه‌ای که به این سرور وصل می‌شود همان شش کار را از نو می‌نویسد: ورود با
کدِ ایمیلی، نگه داشتنِ توکن، تازه کردنش، تپش، خواندنِ اشتراک، اعلان، پشتیبانی و
«نسخهٔ تازه آمده؟». نسخهٔ وبِ دکان یک‌جور نوشته بود، `kar/` جورِ دیگر، و هر باگی
باید دو بار درست می‌شد. این فایل همان را **یک بار** می‌نویسد.

## نصب

```html
<script src="https://api.vill3n.top/sdk/vill3n-sdk.js"></script>
```

همین. هیچ وابستگی‌ای ندارد — نه npm، نه بسته، نه build. فایل خودش را روی
`window.VILL3N` می‌گذارد (و اگر در Node بار شود، روی `module.exports` هم).

## نمونهٔ کار

```js
VILL3N.init({ app: 'shop', version: '2.1.0' });

//  هر تغییری (ورود، تپش، اعلانِ تازه) به این‌جا می‌رسد
VILL3N.onChange((s) => {
  if (!s.signedIn) return showLogin();
  const sub = s.subscription;                 // { daysLeft, color, permanent, label }
  badge.textContent = sub.label;              // «۴۲ روز مانده» یا «دائمی ✓»
  badge.className   = 'badge ' + sub.color;   // green | yellow | red
  bell.hidden       = !s.unread;
});

//  ورود — دو پله، همان کدِ شش‌رقمیِ ایمیل
await VILL3N.login('ali@example.com');
await VILL3N.verify('123456');
```

### گرفتنِ خطاهای برنامه

```js
window.addEventListener('error',              (e) => VILL3N.reportError(e.error, { screen: page }));
window.addEventListener('unhandledrejection', (e) => VILL3N.reportError(e.reason, { screen: page }));
```

### نسخهٔ تازه

```js
const up = await VILL3N.checkUpdate();
if (up.hasUpdate) showBar(`نسخهٔ ${up.latest} آمده است`, up.url);
if (up.mustUpdate) forceUpdate(up.url);        // پایین‌تر از `min_app_version`
```

## فهرستِ کارها

| تابع | چه می‌کند |
|---|---|
| `init({app, version, base, platform, autoHeartbeat, heartbeatMs})` | راه‌اندازی. عکسِ آخرین تپش را از حافظهٔ مرورگر برمی‌دارد و اگر نشست باشد، تپش را شروع می‌کند. |
| `login(email)` | کدِ شش‌رقمی به ایمیل می‌رود (`POST /api/auth/otp/request`). |
| `verify(code[, email])` | کد ⇒ نشست (`/api/auth/otp/verify`). توکن‌ها در حافظهٔ مرورگر می‌نشینند. |
| `logout()` | خروج — توکن روی **سرور** هم باطل می‌شود. |
| `heartbeat({force})` | اشتراک، شمارِ اعلانِ نخوانده و آخرین نسخه، در یک درخواست. هر ۱۵ دقیقه، کَش‌شده. |
| `subscription()` | نمای آمادهٔ «اشتراکِ من» از آخرین تپش، بی درخواستِ تازه. |
| `entitlement()` · `can(key)` | فهرستِ قابلیت‌های باز، و «این یکی باز است؟». |
| `plans()` · `redeem(code, plan)` | پلن‌ها و قیمت‌ها، و سنجیدنِ کدِ تخفیف. **هر دو از سرور.** |
| `notices({limit})` · `markRead(id)` | صندوقِ اعلان و «خواندم». |
| `support.thread({after})` · `support.send(body, subject)` | رشتهٔ پشتیبانی — همان که مدیر در پنل می‌بیند. |
| `reportError(err, context)` | گزارشِ خطا. بی نشست در صف می‌ماند و با ورود می‌رود. |
| `checkUpdate()` | نسخهٔ تازه، نشانیِ دانلود و «اجباری است؟». **بی نشست هم کار می‌کند.** |
| `settings()` · `setCloudSync(on)` | Cloud Sync — انتخابِ خودِ مشتری. |
| `onChange(cb)` | شنونده. خودش تابعِ «لغوِ اشتراک» را برمی‌گرداند. |
| `state()` · `config()` · `stop()` | حالِ فعلی، تنظیمات، و خاموش کردنِ تپش. |

## نمای اشتراک — رنگ یک جا تصمیم گرفته می‌شود

```js
{
  active: true, permanent: false, plan: 'y1',
  startsAt: 1767…, endsAt: 1799…,
  daysLeft: 42,        //  دائمی ⇒ null
  progress: 61,        //  درصدِ نوار
  color: 'green',      //  green > ۳۰ روز · yellow ≤ ۳۰ · red منقضی
  urgent: false,       //  ≤ ۷ روز
  label: '۴۲ روز مانده',   //  دائمی ⇒ «دائمی ✓»
  features: [...], addons: [...], trial: {...}
}
```

⛔ **قاعدهٔ رنگ فقط همین‌جاست.** هر برنامه‌ای که قاعدهٔ خودش را بنویسد، روزی
رنگش با رنگِ پنل فرق می‌کند و مشتری دو حقیقتِ جدا می‌بیند.

## قاعده‌هایی که نباید برگردند

- ⛔ **هیچ قیمتی در SDK نوشته نمی‌شود.** قیمت، مدت و فهرستِ قابلیت‌ها همیشه از
  `/api/plans` و `/api/portal/heartbeat` می‌آیند. آزمونِ `sdk.test.js` هر عددِ
  سه‌رقمی‌ای را که کنارِ `price` بنشیند قرمز می‌کند.
- ⛔ **شناسهٔ حساب هیچ‌وقت فرستاده نمی‌شود** — سرور آن را از خودِ توکن برمی‌دارد
  (`req.shopId` / `req.stationId`). هر چیزی که SDK در بدنه بگذارد نادیده
  گرفته می‌شود، و آزمونِ `portal.test.js` همین را می‌سنجد.
- ⛔ **روی ۴۰۱ فقط یک بار تازه‌سازی و یک بار تلاشِ دوباره.** حلقه زدن جز پنهان
  کردنِ مشکل کاری نمی‌کند؛ ۴۰۱ِ بعد از تازه‌سازی یعنی نشست واقعاً مرده است.
- ⛔ **بی‌اینترنت هیچ‌وقت کسی را از حسابش بیرون نمی‌اندازد.** فقط ۴۰۱/۴۰۳ِ خودِ
  سرور نشست را پاک می‌کند؛ تایم‌اوت و قطعیِ مودم و ۵۰۰ هیچ چیزی را پاک
  نمی‌کنند. عکسِ کهنهٔ تپش سرِ جایش می‌ماند تا برنامه صفحهٔ خالی نبیند.
- ⚠️ **هر خواندن و نوشتنِ حافظهٔ مرورگر پشتِ `try` است.** در پنجرهٔ ناشناس و
  بعضی WebViewها خودِ `localStorage` استثنا پرتاب می‌کند؛ SDK آن‌جا به حافظهٔ
  درون‌برنامه‌ای برمی‌گردد و کارش را می‌کند.
- ⚠️ **نشانیِ سرور از `init({base})` می‌آید** و پیش‌فرضش همان دامنه‌ای است که
  صفحه از آن آمده. برنامه‌های نصبی که نشانی برایشان **قفل** است، همان نشانیِ
  قفل‌شدهٔ خودشان را می‌دهند — قاعدهٔ `AppConfig.kt` و `api-config.js` دست
  نمی‌خورد.
- ⚠️ **هر درخواستی `X-App-Id` را می‌برد** (و `app` را در بدنهٔ ورود، برای سرورِ
  قدیمی که هدر را نمی‌خواند). بی آن، نشستِ اپِ پمپ به بخشِ **دکان** مهر
  می‌خورد و `/api/pump/me` می‌گوید «چنین نشستی نیست».

## آزمون

```
node --test test/sdk.test.js        ۲۰ سنجه
```

SDK در یک `vm` با یک `window`ِ کوچک بار می‌شود و `fetch`ش **واقعاً** به سرورِ
آزمون می‌رود — پس اگر SDK چیزی بخواهد که سرور ندارد، همان‌جا سرخ می‌شود، نه
روی گوشیِ مشتری.

⚠️ **تلهٔ قلمرو**: خطایی که از داخلِ `vm` می‌آید نمونهٔ `Error`ِ قلمروِ آزمون
نیست و آرایه‌اش هم آرایهٔ همان قلمرو نیست. پس `err instanceof Error` و
`assert.deepEqual` روی نتیجهٔ SDK سرخِ دروغ می‌دهند؛ پیام و رشتهٔ JSON را
بسنجید.
