## ۱۲. پروتکل گزارش و تعریف «تمام‌شده»

### ۱۲.۱ تعریف «تمام‌شده» (برای هر قابلیت)

یک قابلیت فقط وقتی ✅ است که **همه** این موارد درست باشد:

1. در همه پلتفرم‌های هدف ساخته شده است، یا استثنایش در STATUS.md ثبت شده است.
2. آزمون واحد و آزمون سناریوهای مرتبط سبز است. سناریوهای ⌨ آزمون خودکار کیبوردی دارند.
3. با کیبورد کامل کار می‌کند، کلیدهایش در `keymap.json` است و در حالت لمسی هم آزموده شده است.
4. حالت‌های بارگذاری، خالی، خطا، آفلاین، بی‌مجوز و فقط‌خواندنی را دارد.
5. متن‌ها دری هستند، کلیدهای ترجمه پشتو و انگلیسی دارند، و اعداد و تاریخ‌ها درست نمایش داده می‌شوند.
6. عمل‌های حساسش مجوز و سابقه دارند.
7. در بودجه کارایی بخش ۹ است.
8. RULES-fa.md (اگر قاعده عوض شده)، STATUS.md و راهنمای F1 به‌روز شده‌اند.
9. اسکرین‌شات کامپیوتر (روشن، تاریک و لمسی) و گوشی در PR هست.
10. هیچ آزمون قبلی نشکسته است.

### ۱۲.۲ قالب گزارش پایان هر نشست

```
## گزارش نشست — {تاریخ هجری} ({تاریخ میلادی})
فاز: …
انجام‌شده:
- {شناسه}: {یک خط توضیح} — PR #…
شواهد:
- آزمون‌ها: سرور … → … ، اندروید … → … ، کامپیوتر … → … ، وب … → …
- اندازه‌گیری‌ها: {عملیات}: قبل … / بعد … (هدف …)
- اسکرین‌شات‌ها: {لینک}
وضعیت شناسه‌ها: ✅ … | 🟡 … | 🔌 … | ⛔ …
مشکلات تازه کشف‌شده: …
تصمیم‌های لازم از صاحب محصول: D-… (گزینه‌ها و پیشنهاد)
قدم بعدی: …
```

### ۱۲.۳ ممنوع‌ها

- اعلام «تمام شد» بدون شواهد.
- دکمه، صفحه یا داده نمایشی در مسیر واقعی.
- حذف یا تغییر بی‌صدای قابلیت موجود.
- تغییر قواعد قفل‌شده بخش ۱.۳ بند ۶ بدون تصمیم صاحب محصول.
- خواندن کل ریپو یا کل RULES-fa.md برای کار متمرکز (قاعده CLAUDE.md).
- اضافه کردن سرویس پولی یا وابستگی CDN بدون تصمیم صاحب محصول.
- ادغام PR با آزمون قرمز.
- ادغام PR پرخطر (پول، صندوق، قالب داده، همگام‌سازی، امضا) بدون پرچم خاموش یا بدون «مرج کن» صاحب محصول (بند ۴ پیام شروع).
- هر کاری از فهرست «توقف اجباری» (بند ۹ پیام شروع) بدون اجازه صریح.
