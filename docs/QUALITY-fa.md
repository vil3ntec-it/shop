# سنجهٔ کیفیتِ کد

ورک‌فلوی `.github/workflows/quality.yml` («کیفیتِ کد») روی هر PR و هر push به `main` اجرا می‌شود و در کمتر از سه دقیقه تمام می‌شود.
کدش در `tools/quality/` است.

- این مرحلهٔ ۱ است: فقط گزارش می‌دهد و هیچ کدی را قالب‌بندی یا عوض نمی‌کند.
- فقط یک سنجه کار را قرمز می‌کند: **شمارهٔ تکراریِ مهاجرت**، آن هم فقط وقتی همین PR فایلِ تازه‌ای با شمارهٔ گرفته‌شده بیفزاید.
- سختگیر کردنِ سنجه‌های دیگر (مرحلهٔ ۲) تصمیمِ صاحب محصول است.

## خواندنِ گزارش

صفحهٔ اجرا در Actions ← Summary.

- هر سنجه یک بخش دارد:
  - ✅ مشکلی نیست.
  - ⚠️ مشکل از پیش بوده است.
  - ❌ همین تغییر چیزی را بدتر کرده است.
  - ℹ️ فقط اطلاع است.
- ستونِ «علت» می‌گوید هر مورد از کجا آمده:
  - **همین تغییر**: این PR فایل را عوض کرده و عدد بزرگ‌تر شده است.
  - **از پیش**: مورد پیش‌تر هم روی main بوده است.
- موردی که «همین تغییر» است روی خطِ همان فایل در diffِ PR هشدار می‌گذارد.
- گامِ همان سنجه نارنجی می‌شود، ولی کار سبز می‌ماند.

| سنجه | چه می‌شمارد | چه وقت ❌ |
|---|---|---|
| اندازهٔ فایل | فایل‌های کدِ غیرِآزمونیِ بالای ۸۰۰ خط | فایلِ تازهٔ بالای ۸۰۰ خط، یا فایلِ بزرگِ خط‌مبنا که بزرگ‌تر شود |
| کمکی‌های تکراری | `afn`، `minorOf`، `StatusPill`، escapeِ HTML و زنجیرهٔ رمزِ `pepper()` بیرون از خانهٔ اصلی‌شان | شمارِ نسخه‌ها از سقف بیشتر شود |
| رشته‌های `'pump'` / `'shop'` | مقایسهٔ درجا در `server/src`، برای هر فایل | فایلی از سقفش بگذرد؛ فایلِ تازه سقفِ صفر دارد |
| برنامهٔ وبِ یخ‌زده | خط و بایتِ `index.html` | بزرگ‌تر شود |
| شمارهٔ مهاجرت‌ها (سد) | شمارهٔ همهٔ فایل‌های `.sql` در `server/migrations`، نام‌های ناهم‌شکل هم | همین PR فایلی با شمارهٔ گرفته‌شده بیفزاید؛ **کار قرمز می‌شود**. تکراریِ ازپیش‌مانده روی main فقط ⚠️ است و نباید تغییرِ نام بگیرد |
| ESLint | فقط قاعده‌های درستی، فقط روی فایل‌های `server/src` که PR عوض کرده؛ بی قاعدهٔ ظاهری و بی `--fix` | خطا (مثلِ `no-undef`)؛ متغیرِ بی‌استفاده فقط هشدار است |
| ES5 | هسته‌های `license/*-core.js` و `debt-book`، `hash-chain`، `keymap`، `ledger-store`، `money`، `report-board` | `let`/`const`/پیکان/`class` در آن‌ها |
| پوشش | آزمون‌های سرور که پایگاه‌داده نمی‌خواهند، با پوششِ خودِ Node | هرگز؛ فقط گزارش |

## سقف‌ها فقط پایین می‌آیند

سقف‌ها در `tools/quality/baseline.json` هستند. الگو همان `HardcodedColorsTest` است.

- **پایین آوردن:** وقتی فایلی را کوچک کردید یا نسخهٔ تکراری را برداشتید، این را بزنید و `baseline.json` را در همان PR کامیت کنید:

  ```
  node tools/quality/quality.mjs --lower-baseline
  ```

  این فرمان هیچ سقفی را بالا نمی‌برد. فایلی که به ۸۰۰ خط یا کمتر برسد، یا شمارش به صفر برسد، از فهرست بیرون می‌رود.
- **بالا بردن:** فقط با ویرایشِ دستیِ `baseline.json`، و دلیلش در متنِ PR.
- **از نو ساختنِ همه:** `--snapshot-baseline`. فقط با دلیل در PR، مثلاً پس از ادغامِ یک بازطراحیِ بزرگ.

> ⛔ مهاجرتی را که روی main است هرگز تغییرِ نام ندهید. `migrate.js` مهاجرتِ اجراشده را با نامِ فایل می‌شناسد، پس نامِ تازه یعنی اجرای دوباره در تولید. شمارهٔ آزاد را فقط به فایلِ تازهٔ همان PR بدهید.

## اجرای محلی

از ریشهٔ مخزن:

```
node tools/quality/quality.mjs                     # سقف‌ها
node tools/quality/quality.mjs --check migrations
node tools/quality/quality.mjs --check eslint --all # همهٔ server/src، نه فقط عوض‌شده‌ها
node tools/quality/quality.mjs --check coverage     # پیش از آن: cd server && npm ci
node --test tools/quality/quality.test.mjs
```

## افزودن قاعده

- قاعده‌ها (کدام فایل، چه الگو، خانهٔ اصلیِ هر کمکی) در `tools/quality/rules.mjs` هستند. سقف‌ها جدا، در `baseline.json`.
- کمکیِ اصلی که ساخته شد (مثلاً `MoneyText.afn`)، مسیرش را در `home`ِ همان قاعده بگذارید تا شمرده نشود.
- برای سنجهٔ تازه:
  - یک فایل در `tools/quality/checks/` بسازید که `run(ctx)` و اگر سقف دارد `update(...)` دارد.
  - آن را در `GROUPS`ِ `quality.mjs` ثبت کنید.
  - آزمونش را در `quality.test.mjs` بنویسید.
