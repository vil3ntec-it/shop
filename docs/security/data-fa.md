## ۳. تمرینِ بازیابی — دستور و عددهای اندازه‌گرفته

```
cd server
npm run restore-drill                         # پشتیبانِ دستیِ تازه ⇒ بازگرداندن در دیتابیسِ جدا ⇒ تطبیق
npm run restore-drill -- <فایل> --migrate     # پشتیبانِ موجود + مهاجرت‌های این نسخه روی کپی
npm run restore-drill -- <فایل> --target postgres://…/empty_db   # بی CREATEDB: دیتابیسِ خالیِ از پیش ساخته
```

کدِ خروج ۰ = برابر؛ ۱ = نابرابر، بی manifest، خالی یا خطا. خروجی فقط عدد است. پشتیبانِ رمزدار همان `BACKUP_PASSPHRASE` ِ
محیط را می‌خواهد (هرگز در خطِ فرمان).

| محیط (محلی، دادهٔ ساختگی) | جدول | بازگرداندن (RTO) | با تطبیق | RPO |
|---|---|---|---|---|
| PostgreSQL ۱۶، `pg_dump` ⇒ `psql` در `shop_drill_*` | ۱۶۸ | ۲٫۴ ثانیه | ۲٫۶ ثانیه | سنِ آخرین پشتیبان: تا `BACKUP_INTERVAL_HOURS` (پیش‌فرض ۲۴ ساعت) برای دیتابیسِ سرور؛ برنامه‌ها هر ۱۲ ساعت پشتیبانِ حساب می‌فرستند |
| PGlite (`loadDataDir` در حافظه) | — | ۱٫۵ ثانیه | ۱٫۶ ثانیه | همان |

عددِ دیتابیسِ واقعی بزرگ‌تر است؛ تمرینِ روی سرور (کارِ صاحب محصول) عددِ واقعی را می‌دهد. هدفِ RPO/RTO هنوز تصمیمِ D-24 است.

## ۴. کارهای صاحب محصول (هیچ‌کدام را عامل انجام نداد)

1. **رمزِ پشتیبان (تصمیمِ در انتظار):** `BACKUP_PASSPHRASE` ِ بلند در محیطِ سرور؛ نسخه‌ای از عبارت **بیرون از** همان ماشین (کاغذ/گاوصندوق).
   بی عبارت، پشتیبانِ رمزدار هرگز برنمی‌گردد — تمرین همین را می‌سنجد.
2. **جدا نگه داشتن:** `BACKUP_PATH` روی دیسکِ دیگر و یک نسخهٔ دوره‌ای بیرون از خانه (همان فایلِ رمزدار). پوشهٔ `accounts/` هم
   همراهش (SEC-DATA-09: آن پوشه رمز ندارد — تا تصمیمِ رمزِ سمتِ سرور، فقط رمزدار بیرون برود).
3. **نخستین تمرینِ واقعی** پس از مرج: `npm run restore-drill -- --migrate` روی سرور (پشتیبانِ تازه، بازگرداندن در حافظه/دیتابیسِ جدا،
   هیچ نوشتنی روی دیتابیسِ زنده) و ثبتِ عدد در HANDOFF؛ سپس ماهانه، و پیش از هر به‌روزرسانیِ دارای مهاجرت.
4. **کمینهٔ دسترسیِ PostgreSQL** (فقط اگر سرور روی PostgreSQL/Docker است — سرورِ خانگیِ PGlite نیازی ندارد):
   - نقشِ مالک `shop_owner` (مالکِ schema؛ فقط برای `npm run migrate`)، نقشِ برنامه `shop_app`:
     `GRANT CONNECT` روی دیتابیس، `GRANT USAGE ON SCHEMA public`، `GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES`،
     `GRANT USAGE, SELECT ON ALL SEQUENCES` و همان‌ها با `ALTER DEFAULT PRIVILEGES FOR ROLE shop_owner`؛ بی `CREATE` روی schema،
     بی SUPERUSER، بی CREATEDB.
   - چون `createApp` مهاجرت را خودش می‌زند، این جدایی یعنی مهاجرت پیش از بالا آمدن با نقشِ مالک — تغییرِ راه‌اندازی است و با
     برنامهٔ بازگشت انجام شود (هیچ‌کدام در این PR نیست).
   - پشتیبان: نقشِ فقط‌خواندنی (`pg_read_all_data`) برای `pg_dump`؛ تمرین با `--target` روی دیتابیسِ خالیِ از پیش ساخته (بی CREATEDB).
5. «مرج کن» برای #586 (رفتارِ پولیِ نصب‌شده، بی پرچم چون نشت را می‌بندد) و PRِ همین سند.
