# برنامهٔ کامپیوترِ فروشگاه (`desktop/`)

خواستهٔ صاحب مخزن: «برنامهٔ نیتیوِ کامپیوتر… سایت نباشد که بگیری برنامهٔ
کامپیوتری کنی؛ خودِ برنامه را همان‌جوری که توی گوشی است برای کامپیوتر هم
بساز و نیتیو ۱۰۰٪ باشد — همهٔ منطق‌ها، همهٔ بخش‌ها، همهٔ ریزه‌کاری‌ها.»

## چه ساخته شد

برنامهٔ اندروید (`android-native/`) سراسر Kotlin و Jetpack Compose است.
**Compose Desktop** همان Compose است که به‌جای اندروید روی JVM و Skia
می‌نشیند — بی WebView، بی مرورگر، بی HTML. پس برنامهٔ کامپیوتر
**همان فایل‌های** `android-native/app/src/main/java` را کامپایل می‌کند:

```
android-native/app/src/main/java  ──(جدولِ عبارت)──▶  build/generated/android-src ─┐
desktop/src/shim/kotlin   (android.* و androidx.* روی کامپیوتر)                   ├─▶ Tohid (JVM + Skia)
desktop/src/main/kotlin   (ورودِ برنامه + هشت جایگزینِ کامپیوتری)                 ┘
```

- هر تغییری در برنامهٔ گوشی **خودبه‌خود** به کامپیوتر می‌رسد. کپی‌ای از
  منطق نیست که روزی از هم جدا بیفتند.
- **۳۸۰ آزمونِ واحدِ اندروید** (`android-native/app/src/test`) روی همین
  ساخت می‌دوند (`./gradlew test`) — این سندباکس SDKِ اندروید ندارد، پس
  این‌جا تنها جایی است که آن آزمون‌ها بیرون از CIِ اندروید سنجیده می‌شوند.
- همان سرور، همان حساب، همان دکان، همان اشتراک: `BuildConfig`ِ
  کامپیوتر نشانی و شناسهٔ برنامه را از **`android-native/gradle.properties`**
  می‌خواند. ⛔ جای سومی برای `tohid.apiBase` و `tohid.appId` نسازید.

## لایهٔ سازگاری (`src/shim/`)

همان نام‌های اندروید با پیاده‌سازیِ کامپیوتری، تا فایل‌های اندروید
دست‌نخورده کامپایل شوند:

| اندروید | کامپیوتر |
|---|---|
| `Context`، `filesDir`، `SharedPreferences` | `DesktopContext` — پوشهٔ دادهٔ استانداردِ هر سیستم؛ تنظیمات JSON با نوشتنِ اتمی |
| `WorkManager` / `CoroutineWorker` | همان کارها داخلِ فرآیند؛ `KEEP`/`UPDATE`/`REPLACE` و `retry` با عقب‌نشینی |
| اعلان (`NotificationManager`) | اعلانِ سینیِ سیستم |
| `rememberLauncherForActivityResult` | پنجرهٔ انتخاب/ذخیرهٔ فایلِ خودِ سیستم؛ اجازه‌ها همه داده‌شده |
| `BackHandler` | کلیدِ **Esc** و دکمهٔ «عقب»ِ ماوس |
| `Bitmap`، `Canvas`، `StaticLayout` | Java2D — پس **فاکتورِ چاپی همان `Receipt.kt`ِ گوشی است** |
| USB (`UsbManager`) | **چاپگرهای نصب‌شده در سیستم**؛ بایت‌های ESC/POSِ `ThermalPrinter.render` خام (RAW) به صفِ چاپگر |
| `WebView` + `PrintManager` (چاپِ گزارش) | صفحهٔ HTML در مرورگرِ سیستم با پنجرهٔ چاپ (و «ذخیره به PDF») |
| `LocalConfiguration.screenWidthDp` | پهنای پنجره — پس `Responsive.kt` پنجرهٔ پهن را «WIDE» می‌بیند |
| `Build.MODEL` | «کامپیوتر · ویندوز · نامِ کامپیوتر» — همان که در فهرستِ نشست‌ها دیده می‌شود |

## جایگزین‌ها (`src/main/kotlin`، با پسوندِ `Desk`)

فقط هشت فایل، با **همان API**:

| فایل | چرا |
|---|---|
| `MainActivity.kt` ⇒ `desktop/Main.kt` | پنجره، سینی، یک‌نمونه، Esc، بزرگ‌نمایی |
| `core/net/TokenStore.kt` | Keystoreِ اندروید نیست؛ توکن‌ها AES-GCM با کلیدِ جدا و فقط-صاحب (`SecretBox`) |
| `scan/BarcodeScanner.kt` | CameraX/ML Kit نیست — **بارکدخوانِ سخت‌افزاری** (USB/بلوتوث) که صفحه‌کلید است |
| `update/Updater.kt` | نصابِ هر سیستم به‌جای APK؛ فایلِ ناجورِ جمعِ کنترلی نصب نمی‌شود |
| `data/Fingerprint.kt` | اثرِ انگشت از JVM در دسترس نیست ⇒ همان رمزِ شش‌رقمی |
| `data/GoogleSignIn.kt` | Credential Manager نیست (دکمه در برنامه هم خاموش است) |
| `data/Migration.kt` | نسخهٔ قبلیِ کامپیوتری نبوده که دفترش آورده شود |
| `sync/Integrity.kt` | امضای APK مالِ اندروید است؛ قفلِ واقعی مجوزِ امضاشدهٔ سرور است |

## جدولِ عبارت («گوشی» ⇒ «کامپیوتر»)

فایل‌های اندروید پیش از کامپایل از جدولِ `phrases` در `build.gradle.kts`
می‌گذرند: «روی همین گوشی» ⇒ «روی همین کامپیوتر»، «دوربین بارکدخوان» ⇒
«بارکدخوان»، «برنامهٔ اندروید» ⇒ «برنامهٔ کامپیوتر» (که به درخواستِ خرید
هم می‌رود و مدیر می‌بیند از کجا آمده)…

⚠️ عبارتی که دیگر در کدِ اندروید نباشد هنگامِ ساخت **هشدار** می‌دهد —
یعنی نوشتهٔ برنامهٔ گوشی عوض شده و جدول باید با آن برود.

## مالِ خودِ کامپیوتر

- **سینیِ سیستم**: بستنِ پنجره برنامه را نمی‌بندد؛ همگام‌سازیِ
  پانزده‌دقیقه‌ای، سوکتِ زنده، پشتیبانِ دوازده‌ساعته و دیدبانِ موجودی
  پشتِ صحنه می‌مانند. «خروج» در منوی سینی.
- **یک نمونه**: اجرای دوم فقط پنجرهٔ اولی را جلو می‌آورد — دو پنجره یعنی
  دو نویسنده روی یک دفتر.
- **Ctrl + / − / 0**: بزرگ‌نمایی، ذخیره‌شده.
- **صفحهٔ قفل** رقم‌های صفحه‌کلید (و رقم‌های فارسی) و Backspace را
  می‌پذیرد — این تغییر در خودِ `AppLock.kt` است و روی گوشیِ با صفحه‌کلید
  هم کار می‌کند.

## آن‌چه روی کامپیوتر نیست — و عمداً پنهان نشده

- **اسکن با وب‌کم**: کادرِ دوربین روی کامپیوتر گیرندهٔ بارکدخوانِ
  سخت‌افزاری است و کادرِ «بارکد را دستی وارد کنید» سرِ جایش است.
- **بلوتوثِ کلاسیکِ مستقیم** (SPP): چاپگرِ بلوتوثی را در سیستم جفت و نصب
  کنید؛ از برگهٔ «چاپگر سیستم» دیده می‌شود.
- **لوکیشن**: کامپیوتر GPS ندارد؛ `DeviceLocation` «پیدا نشد» می‌گوید که
  طبقِ قرارش جلوی هیچ کاری را نمی‌گیرد.
- **امضای کد**: نصاب‌ها هنوز امضای مایکروسافت/اپل ندارند. ویندوز
  SmartScreen «More info ⇒ Run anyway» و مک «راست‌کلیک ⇒ Open» می‌خواهد.

## ساخت

```
cd desktop
./gradlew run                     # اجرا
./gradlew test                    # آزمون‌های اندروید روی کامپیوتر
./gradlew packageMsi|packageDmg|packageDeb
./gradlew -Pdev=true run          # به سرورِ محلی (TOHID_API_BASE_DEV)، http پذیرفته
```

- `TOHID_OFFLINE_M2`: مخزنِ Mavenِ محلی برای `androidx.*`، وقتی شبکه
  `dl.google.com` را نمی‌رساند (CI همین بسته را می‌سازد).
- `-Dtohid.shot=<پوشه>` و `-Dtohid.shot.script=…` (`DevShot.kt`): سنجشِ
  چشمیِ برنامهٔ واقعی روی Xvfb — کلیک، تایپ، عکس. در نسخهٔ کاربر خاموش.

## انتشار

`.github/workflows/tohid-desktop.yml`: کامپایل و آزمون ⇒ نصاب روی
`windows-2022` (MSI)، `macos-14` و `macos-15-intel` (DMG) و `ubuntu-22.04`
(DEB) ⇒ فقط از `main`، روی برچسبِ `tohid-desktop`، فایل‌ها یکی‌یکی و
`version.txt` آخر (همان درسِ «Error saving asset»).

⛔ `upgradeUuid`ِ ویندوز در `build.gradle.kts` **هرگز** عوض نشود: ویندوز با
آن می‌فهمد نسخهٔ تازه روی همان برنامه نصب می‌شود، نه کنارش.
