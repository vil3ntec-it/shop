# بخشِ پمپ‌بنزین

خواستهٔ صاحب مخزن: «سرور و ادرس و دامنه یکی باشه اما جدا باشن، چون هم
برنامه جداگانه است هم حساب کتاب‌ها. برای هر حساب تو فولدرِ سرورها حسابِ
طرف با اطلاعات بره، و به هر حساب اشتراک بدم یا ندم، مثل بخشِ شاپ.»

پس همان سرور و همان دامنه — `https://api.vill3n.top` — ولی زیرِ
`/api/pump/…` و روی جدول‌های خودش.

---

## یک نگاه

```
                     api.vill3n.top
        ┌──────────────────┴──────────────────┐
   /api/shop/…                           /api/pump/…
   دکان‌ها، فروش، انبار                  پمپ‌ها، پوشهٔ هر پمپ
   subscriptions                        station_subscriptions
   vip_codes                            station_vip_codes
        └──────────────────┬──────────────────┘
                       users
              یک لاگینِ گوگل برای هر دو
```

**چه چیزی مشترک است:** فقط `users`. یک نفر با یک حساب هم دکان دارد هم
پمپ؛ دو حساب ساختن برای یک آدم همان چیزی است که قاعدهٔ «یک سرور، یک
حساب» منعش کرده.

**چه چیزی جداست:** هر چیزِ دیگری. پمپ، اشتراک، کدِ شش‌رقمی، قابلیت‌ها،
دورهٔ آزمایشی، و پوشهٔ داده.

---

## چرا جدول‌های جدا و نه یک ستونِ `app`

`subscriptions.shop_id` کلیدِ خارجی به `shops` دارد. برای جا دادنِ پمپ در
همان ردیف یا باید آن کلید برداشته می‌شد — و دفترِ زندهٔ شاپ بی‌حفاظ
می‌ماند — یا ستونی ساخته می‌شد که نیمی از ردیف‌ها همیشه خالی‌اش بگذارند.

پس جدول‌ها جدا شدند و **کد مشترک ماند**: `lib/tenancy.js` نامِ جدولِ هر
بخش را می‌گوید و `subscriptions.js`، `vip-codes.js` و `entitlement.js`
کارخانه‌اند — `build(T)` همان منطق را روی جدول‌های یک بخش می‌بندد.

```js
subs.grant(shopId, …)            // بخشِ دکان — مثل همیشه
subs.pump.grant(stationId, …)    // بخشِ پمپ — همان کد، دفترِ دیگر
```

نامِ جدول پارامترِ پرس‌وجو نمی‌شود، پس این نام‌ها در متنِ SQL می‌نشینند.
امن‌اند چون **فقط** از `lib/tenancy.js` می‌آیند و `byApp()` هر نامِ
ناشناخته را رد می‌کند.

## پوشهٔ هر پمپ

همان چیدمانی که سرورِ خانگی دارد، این‌بار روی ابر:

```
station_files (station_id, path)
  live.json      عکسِ زندهٔ پمپ — برنامهٔ کامپیوتر می‌نویسد
  inbox.json     صندوقِ ورودی — گوشیِ کارمند هم می‌نویسد
  station.json   شناسنامهٔ پمپ
  …              هر نامِ دیگری، بی نیاز به مهاجرتِ تازه
```

⚠️ **این نسخه است، نه اصل.** دفترِ پمپ روی کامپیوترِ خودِ پمپ می‌ماند —
همان قاعدهٔ «برنامهٔ نیتیو اصلِ اطلاعات است». پوشهٔ ابری برای آن است که
گوشیِ کارمند از هر جای دنیا ببیندش و اگر کامپیوتر سوخت، داده گم نشود.

⚠️ **فقط صاحب و مدیر می‌نویسند.** `inbox.json` عمداً استثناست: راهِ
برگشتِ داده از گوشیِ کارمند همان است و بی آن، «صندوقِ ورودی» اصلاً وجود
ندارد.

---

## نشانیِ سرورِ خانگی — چرا اپِ کارمند دیگر آدرس نمی‌پرسد

آی‌پیِ سرورِ خانگی با هر بار روشن شدنِ مودم عوض می‌شود. تا دیروز کارمند
باید نشانی را دستی می‌نوشت یا کیو‌آر اسکن می‌کرد، و همان نشانی بی‌صدا از
کار می‌افتاد.

حالا:

1. برنامهٔ کامپیوتر هر بار که بالا می‌آید `POST /api/pump/home` می‌زند
2. کارمند با گوگل وارد می‌شود و `GET /api/pump/me` نشانی را به او می‌دهد
3. اپ مستقیم وصل می‌شود — بی آنکه از کسی چیزی پرسیده باشد

## مسیرها

### برنامه و اپ

| مسیر | چه می‌کند |
|---|---|
| `GET /api/pump/features` | کاتالوگِ بخش‌ها (باز، بی‌نیاز به ورود) |
| `GET /api/pump/me` | پمپِ من + وضعیتِ اشتراک + نشانیِ خانگی |
| `POST /api/pump` | ساختِ پمپ (هر حساب یکی) |
| `PATCH /api/pump` | نام و نشانی |
| `POST /api/pump/home` | ثبتِ نشانیِ سرورِ خانگی |
| `GET /api/pump/members` | اعضا |
| `GET /api/pump/subscription` | اشتراک و تاریخچه‌اش |
| `POST /api/pump/vip/redeem` | خرجِ کدِ شش‌رقمی |
| `POST /api/pump/license` | مجوزِ امضاشدهٔ این دستگاه |
| `GET /api/pump/files` | فهرستِ پوشه |
| `GET /api/pump/files/:path` | یک فایل |
| `PUT /api/pump/files/:path` | نوشتنِ یک فایل |

### پنلِ مدیریت — `/api/admin/pump/…`

`stations` · `stations/:id` · `stations/:id/status` · `subscriptions` ·
`subscriptions/:id/status` · `subscriptions/expiring` · `vip-codes` ·
`vip-codes/:id/revoke` · `stats` · `features`

همه زیرِ همان `requireAdmin`ی که بقیهٔ مسیرهای مدیریت دارند.

## قابلیت‌ها

کلیدها همان نام‌هایی است که `StationSnapshot` در برنامهٔ نیتیو به‌کار
می‌برد، تا قفل و عکسِ داده یک زبان داشته باشند.

| همیشه باز | رایگان | با اشتراک |
|---|---|---|
| `dashboard` خانه | `expense` مصارف | `safe` گاوصندوق |
| `settings` تنظیمات | `extraincome` عایدات | `sarrafi` صرافی |
| `debtors` قرض‌داران | `reports` گزارش و چاپ | `chakana` چکنه |
| | | `invoice` فاکتورها |
| | | `storage` خریدِ تیل |
| | | `staff` کارمندان |
| | | `companies` شرکت‌های تیل |
| | | `amanat` امانت |
| | | `kar_app` اپِ کارمندان |
| | | `bot` رباتِ دستیار |
| | | `messenger` پیام‌رسان |
| | | `cloud` پوشهٔ ابری و پشتیبان |
| | | `multi_device` چند دستگاه |

**چرا `debtors` همیشه باز است:** صاحبِ پمپ باید همیشه بتواند دفترِ خودش
را ببیند، حتی با اشتراکِ تمام‌شده. گروگان گرفتنِ داده سریع‌ترین راهِ از
دست دادنِ اعتماد است.

هر اشتراک می‌تواند زیرمجموعه‌ای از قابلیت‌های پولی را باز کند — در پنل،
با تیک. اگر چیزی تیک نخورد، همهٔ پولی‌ها باز می‌شوند.

## مجوز

`aud` بخشِ پمپ `tohid-pump-app` است، نه `tohid-shop-app`.

هر دو بخش یک کلید خصوصی دارند — کلید مالِ سرور است نه مالِ برنامه — ولی
اگر `aud` هم یکی بود، مجوزی که برای دکانی صادر شده روی برنامهٔ پمپ هم
می‌نشست: امضا درست، دستگاه درست، و برنامه هیچ دلیلی برای رد کردنش نداشت.
یک اشتراکِ دکان، یک اشتراکِ پمپ را هم مجانی می‌کرد.

## دورهٔ آزمایشی

کلیدش `pump_trial_days` است (پیش‌فرض ۱۴)، جدا از `trial_days`ِ دکان —
وگرنه عوض کردنِ آن برای دکان‌ها ناخواسته پمپ‌ها را هم عوض می‌کرد.

```
PATCH /api/admin/config   { "pump_trial_days": "30" }
```

## آزمون

```
npm test                        # همه — ۱۵۸ سنجه
node --test test/pump.test.js   # فقط بخشِ پمپ — ۱۵ سنجه
```

دو سنجهٔ مرزی عمداً آن‌جا هستند و نباید برداشته شوند:

- «اشتراکِ دکان، پمپِ همان آدم را باز نمی‌کند»
- «قابلیتِ دکان در اشتراکِ پمپ نمی‌نشیند»

اگر روزی کسی دو بخش را یکی کرد، همین دو سنجه اول قرمز می‌شوند.
