# VILL3N Sync v1 — پروتکلِ مشترکِ همگام‌سازی

بخشِ ۲۰ پرامپتِ VILL3N، همان‌طور که روی سرور پیاده شده. برنامهٔ دکان
(اندروید و وب) و برنامهٔ پمپ (کامپیوتر) هر دو با همین نوشته می‌شوند.

---

## ۰. قانونِ طلایی

**هرگز کلِ داده به سرور نمی‌رود، فقط *تغییر*.** اگر یک اسم پاک شود، یک
رکوردِ چندصدبایتی می‌رود («ردیفِ X پاک شد»)، نه کلِ فهرست. سنجه‌اش عددی
است: بدنهٔ یک حذف زیرِ یک کیلوبایت.

---

## ۱. دفترِ تغییرات (Oplog)

هر برنامه یک جدولِ محلیِ `oplog` دارد. هر تغییر **اول** در دیتابیسِ محلی
می‌نشیند، بعد یک op نوشته می‌شود:

```json
{
  "op_id":   "01J8ZK3Q7X…",   // ULID — یکتا و مرتب بر اساس زمان
  "ts":      1758300000123,   // زمانِ دستگاه
  "table":   "customers",
  "row_id":  "c_88",          // ULID/UUID که خودِ برنامه ساخته، نه شمارهٔ خودافزا
  "type":    "update",        // insert | update | delete
  "fields":  { "name": "احمد" },   // فقط فیلدهای عوض‌شده
  "hash":    "sha256(…)"
}
```

- `update` فقط فیلدهای عوض‌شده را دارد.
- `delete` هیچ فیلدی ندارد و روی سرور **نرم** است (`deleted_at`)؛ هیچ
  داده‌ای نابود نمی‌شود و از پنل برمی‌گردد.
- `insert` کلِ رکوردِ تازه را دارد.
- شناسه‌ها ULID/UUID‌اند تا دو دستگاهِ آفلاین تصادم نکنند.

---

## ۲. مسیرها

همه زیرِ `/api/sync/v1` و با `Authorization: Bearer <access>`.

| مسیر | کار |
|---|---|
| `POST /push` | `{device_id, schema_version, ops[]}` ⇒ نتیجهٔ هر op + `cursor` |
| `GET /pull?device_id=&since=` | opهای **دستگاه‌های دیگر** پس از cursor |
| `GET /snapshot` | یک‌بار برای دستگاهِ تازه (gzip) |
| `GET /status?device_id=` | حالِ همین دستگاه: آخرین op، صف، cursor |
| `GET /conflicts` · `GET /deleted` | تعارض‌ها و ردیف‌های حذف‌شده |
| `wss /api/sync/v1/live` | `{event:"changed", cursor}` ⇒ برنامه Pull می‌کند |
| `POST /api/errors` | گزارشِ خطای برنامه |

نتیجهٔ هر op: `applied` · `duplicate` · `rejected` (با دلیل). فقط
`applied` و `duplicate` روی دستگاه `synced=true` می‌شوند.

سقف‌ها: **۲۰۰ op** یا **۲۵۶ کیلوبایت** در هر دسته.

---

## ۳. حلِ تعارض

- **سطحِ فیلد، نه رکورد**: دستگاه A نام را عوض کند و B تلفن را، هر دو
  می‌مانند.
- **یک فیلد از دو طرف**: ترتیبِ رسیدن به سرور داور است، و نسخهٔ بازنده در
  `sync_conflicts` می‌ماند و از پنل **برمی‌گردد**. هیچ‌چیز بی‌صدا حذف
  نمی‌شود.
- **حذف در برابر ویرایش**: ویرایشِ پس از حذف ردیف را زنده می‌کند.
- **مبالغ و شمارنده‌ها دلتا می‌روند**: `{"stock": {"$inc": -3}}`. با
  «مقدارِ تازه»، دو فروشِ هم‌زمان از دو دستگاه یکی‌شان گم می‌شد.

---

## ۴. نسخهٔ Schema

- هر برنامه `schema_version` می‌فرستد. نسخهٔ سرور در `app_schema` است و
  سرِ بالا آمدن از کد نوشته می‌شود.
- **برنامهٔ قدیمی‌تر**: opهایش پذیرفته و همان‌جا تبدیل می‌شوند
  (`sync-v1-migrations.js`)، و پاسخ `upgrade_available: true` می‌گیرد.
- **برنامهٔ جدیدتر**: `426 UPGRADE_REQUIRED` و **هیچ opی اعمال نمی‌شود**؛
  برنامه opها را نگه می‌دارد تا سرور به‌روز شود.

هر جدول یا فیلدِ تازه = یک پله بالاتر در `sync-v1-migrations.js` **و** یک
migration در خودِ برنامه با همان شماره.

---

## ۵. مرزها — قاعده‌هایی که نباید بشکنند

- ⛔ **شناسهٔ حساب از توکن می‌آید، نه از درخواست.** بی این، یک دکان
  می‌توانست در دفترِ دکانِ دیگری بنویسد.
- ⛔ **هر پرس‌وجو `app` را شرط می‌کند** — یک جدول برای دو بخش است.
- ⛔ **نامِ جدول از فهرستِ سفید می‌آید.** هر نامِ بیرونِ فهرست `rejected`
  می‌گیرد. دکان: همان مجموعه‌های `lib/sync.js`؛ پمپ: موجودیت‌های دفترِ
  برنامهٔ کامپیوتر.
- ⛔ **`op_id` تکراری دوباره اعمال نمی‌شود.** اینترنتی که وسطِ ارسال قطع
  شود و دسته دوباره برود، چیزی را دوباره نمی‌نشاند.
- ⚠️ Pull هیچ‌وقت opهای خودِ دستگاه را برنمی‌گرداند.

---

## ۶. آن‌چه برنامه باید انجام دهد

1. هر تغییر ⇒ یک op در `oplog`ِ محلی. **هیچ نوشتنِ مستقیمی** بیرون از
   لایه‌ای که op می‌سازد.
2. Workerِ پس‌زمینه: هر ۲ ثانیه (یا ۵۰۰ms پس از هر تغییر) opهای نفرستاده
   را دسته‌ای Push کند، با عقب‌نشینیِ نمایی و بی‌نهایت تلاش.
3. `cursor` را نگه دارد و با هر پیامِ `changed` یا هر ۳۰ ثانیه Pull کند.
4. دستگاهِ تازه: یک بار `snapshot`، بعد فقط تغییرها.
5. وضعیتِ Sync را نشان بدهد: سبز (همگام)، زرد (در صف)، خاکستری (آفلاین)،
   قرمز (خطا).

---

## ۷. آزمون

`npm run test:login` — شانزده سنجهٔ Sync، از جمله هر بندِ معیارِ پذیرشِ
۲۰.۱۰: حذفِ زیرِ یک کیلوبایت، سه روز آفلاین بی گم شدن، دو فیلد از دو
دستگاه، دو `$inc` هم‌زمان، Snapshotِ گوشیِ نو، و برنامهٔ قدیمی/جدید در
برابرِ سرور.

✅ **سمتِ برنامهٔ دکان نوشته شد** — وب و اندروید، هر دو:
`license/sync-core.js` · `license/sync-engine.js` و
`android-native/…/sync/v1/*`. شرح، انحراف‌ها و آن‌چه هنوز نیست:
`docs/SYNC-CLIENT-fa.md`.

⚠️ **برنامهٔ پمپ (کامپیوتر) هنوز `oplog` ندارد.** برای آن طرف، این
پروتکل همچنان یک‌طرفه است و نباید «انجام شد» نوشته شود.
