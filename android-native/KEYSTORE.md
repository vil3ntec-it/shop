# کلید امضا

کلیدی که برنامه با آن امضا می‌شود، تنها چیزی است که اندروید برای شناختنِ
سازنده دارد. هر فایلی که با همین کلید امضا شود، روی گوشیِ کاربر «همان
برنامه» حساب می‌شود و روی نصبِ قبلی می‌نشیند.

تا امروز خودِ فایلِ کلید و رمزش هر دو داخلِ مخزن بودند.

## وضعیت امروز

ساخت، کلید را از این متغیرها می‌خواند و اگر نبودند به فایلِ داخلِ مخزن
برمی‌گردد — تا هیچ ساختی نشکند:

| متغیر | چیست | پیش‌فرض |
|---|---|---|
| `TOHID_KEYSTORE` | مسیرِ فایلِ کلید | `app/tohid-release.jks` |
| `TOHID_KEYSTORE_PASSWORD` | رمزِ فایل | `tohid-shop` |
| `TOHID_KEY_ALIAS` | نامِ کلید | `tohid` |
| `TOHID_KEY_PASSWORD` | رمزِ خودِ کلید | همان رمزِ فایل |

ورک‌فلو هم اگر `TOHID_KEYSTORE_B64` تنظیم شده باشد از آن می‌سازد، وگرنه
یک هشدار می‌دهد و با فایلِ داخلِ مخزن ادامه می‌دهد.

## سه گامِ باقی‌مانده — دستِ شماست

اینها را فقط صاحبِ مخزن می‌تواند انجام دهد، چون افزودنِ secret دسترسی
مالکیت می‌خواهد.

**۱) کلید را به base64 بگیرید:**

```bash
base64 -w0 android-native/app/tohid-release.jks > keystore.b64
```

**۲) در گیت‌هاب، `Settings ← Secrets and variables ← Actions ← New
repository secret`، چهار تا بسازید:**

| نام | مقدار |
|---|---|
| `TOHID_KEYSTORE_B64` | محتوای `keystore.b64` |
| `TOHID_KEYSTORE_PASSWORD` | `tohid-shop` |
| `TOHID_KEY_ALIAS` | `tohid` |
| `TOHID_KEY_PASSWORD` | `tohid-shop` |

بعد `keystore.b64` را از روی رایانه پاک کنید و خودِ فایلِ `.jks` را جای
امنی نگه دارید. **اگر این فایل گم شود، هیچ‌وقت نمی‌شود نسخهٔ تازه‌ای داد
که روی نصبِ کاربرها بنشیند** — باید برنامه را حذف و از نو نصب کنند.

**۳) بعد از اینکه یک ساختِ موفق دیدید، فایل را از مخزن بردارید:**

```bash
git rm --cached android-native/app/tohid-release.jks
git commit -m "کلید امضا از مخزن برداشته شد"
```

`.gitignore` از قبل جلوی برگشتنش را می‌گیرد.

## دو چیزی که باید بدانید

**برداشتن از امروز، گذشته را پاک نمی‌کند.** کلید در تاریخچهٔ گیت می‌ماند
و هر کسی که مخزن را کلون کرده باشد آن را دارد. برای پاک کردنِ واقعی باید
تاریخچه بازنویسی شود (`git filter-repo`) و همه دوباره کلون کنند.

**عوض کردنِ کلید هزینه دارد.** اگر تصمیم بگیرید کلید را قابلِ‌اعتماد
نمی‌دانید و کلیدِ تازه بسازید، کاربرانِ فعلی نمی‌توانند به‌روزرسانی
بگیرند: باید برنامه را حذف کنند و از نو نصب کنند، و اطلاعاتِ روی گوشی‌شان
با آن می‌رود مگر اینکه اول پشتیبان بگیرند.

انتخاب بینِ این دو با شماست:

- **نگه داشتنِ همین کلید** — به‌روزرسانی‌ها سالم می‌مانند، ولی هر کسی که
  تا امروز مخزن را دیده، کلید را دارد.
- **کلیدِ تازه** — از این به بعد امن است، ولی همهٔ کاربرانِ فعلی باید یک
  بار حذف و نصب کنند.

اگر مخزن خصوصی بوده و فقط خودتان به آن دسترسی داشته‌اید، گزینهٔ اول
منطقی است.
