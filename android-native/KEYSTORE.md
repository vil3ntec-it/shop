# کلید امضا

کلیدی که برنامه با آن امضا می‌شود، تنها چیزی است که اندروید برای شناختنِ
سازنده دارد. هر فایلی که با همین کلید امضا شود، روی گوشیِ کاربر «همان
برنامه» حساب می‌شود و روی نصبِ قبلی می‌نشیند.

## ⛔ رخدادِ SEC-ART-05a (۱۴۰۵/۰۸/۱۰)

تا امروز خودِ فایلِ کلید (`app/tohid-release.jks`) و رمزِ پیش‌فرضش (در همین فایل و در
`app/build.gradle.kts`ِ هر دو برنامه) در مخزن بودند، و **مخزن عمومی است**. نسخه‌های منتشرشدهٔ
«فروشگاه من» (پایدار و آزمایشی) و «مدیریت» با همین کلید امضا شده‌اند (اثرِ انگشتِ گواهیِ APKِ منتشرشده
با گواهیِ فایلِ مخزن یکی است — `docs/security/artifacts-fa.md`).

یعنی: **این کلید لورفته است.** هر کسی که مخزن را دیده یا کلون کرده می‌تواند APKی بسازد که گوشی‌ها
به‌روزرسانیِ «همان برنامه» بدانند و `Integrity.isGenuine()` هم «اصل» بگوید. برداشتنِ فایل از امروز
گذشته را پاک نمی‌کند: کلید در تاریخچهٔ Git می‌ماند. بازنویسیِ تاریخچه (`git filter-repo`) تصمیمِ
صاحب محصول است و حتی آن هم چیزی را که بیرون رفته برنمی‌گرداند — فقط چرخش.

## وضعیت امروز

ساخت، کلید را **فقط** از این متغیرها می‌خواند. هیچ پیش‌فرض و هیچ فایلی در مخزن نیست؛ ساختِ
release/preview بی آن‌ها شکست می‌خورد (debug و آزمون‌های واحد بی کلید کار می‌کنند):

| متغیر | چیست |
|---|---|
| `TOHID_KEYSTORE` | مسیرِ فایلِ کلید (ورک‌فلو از secretِ `TOHID_KEYSTORE_B64` می‌سازدش) |
| `TOHID_KEYSTORE_PASSWORD` | رمزِ فایل |
| `TOHID_KEY_ALIAS` | نامِ کلید درونِ فایل |
| `TOHID_KEY_PASSWORD` | رمزِ خودِ کلید (نبود ⇒ همان رمزِ فایل) |

ورک‌فلوها (`tohid-native.yml`، `tohid-admin.yml`) اگر `TOHID_KEYSTORE_B64` نباشد **قرمز** می‌شوند؛
دیگر هشدار نمی‌دهند و به فایلِ مخزن برنمی‌گردند. اگر کلید هست ولی خوانده نشود، ساخت می‌شکند (پیش‌تر
اثرِ انگشت خالی می‌ماند و سنجشِ امضای برنامه بی‌صدا خاموش می‌شد).

## گام‌های صاحب محصول

**۱) فوری — تا ساخت‌ها دوباره سبز شوند:** چهار secret در `Settings ← Secrets and variables ←
Actions`: `TOHID_KEYSTORE_B64` (محتوای base64ِ فایلِ کلید)، `TOHID_KEYSTORE_PASSWORD`،
`TOHID_KEY_ALIAS`، `TOHID_KEY_PASSWORD`. اگر همان کلیدِ امروز را می‌گذارید (تا به‌روزرسانیِ نصب‌ها نشکند)،
فایل را از نسخهٔ خودتان یا از تاریخچهٔ Git روی کامپیوترِ خودتان بردارید — هرگز در چت یا issue نگذارید.
بعد از آن یک بار Run workflow یا pushِ تازه.

**۲) چرخش — چون کلید لورفته است:** کمینهٔ برنامه API 24 است و امضای v3 روشن است، پس می‌شود
کلید را **بی حذف و نصبِ دوبارهٔ** کاربرها عوض کرد:

1. کلیدِ تازه روی کامپیوترِ خودتان: `keytool -genkeypair -keystore new.jks -alias tohid -keyalg EC -groupname secp256r1 -validity 10000`
2. زنجیرهٔ چرخش: `apksigner rotate --out lineage.bin --old-signer --ks old.jks --new-signer --ks new.jks`
3. پیش از نخستین نسخهٔ چرخیده، `Integrity.kt` باید اثرِ انگشتِ **هر دو** کلید را بپذیرد (قاعدهٔ «کلیدها» در
   `docs/RULES-fa.md`)، وگرنه `isGenuine()` روی گوشی‌های تازه‌شده false می‌شود و اشتراک‌ها بسته می‌شوند.
4. امضای release با `apksigner sign --lineage lineage.bin` (AGP خودش lineage نمی‌گیرد؛ گامِ CI جدا).
   گوشی‌های اندروید ۹ به بالا از آن پس فقط امضای کلیدِ تازه را می‌پذیرند؛ اندروید ۷ و ۸ امضای v3 را
   نمی‌فهمند و همچنان کلیدِ قدیم را می‌بینند — آن‌ها تا ارتقا در معرضِ همان کلیدِ لورفته می‌مانند.
5. secretها را به کلیدِ تازه ببرید؛ فایلِ قدیم را فقط برای ساختنِ زنجیره نگه دارید، جای امن و بیرون از مخزن.

**۳) تاریخچه (اختیاری):** بازنویسی با `git filter-repo` و کلونِ دوبارهٔ همه — فقط جلوی دیدنِ تازه را
می‌گیرد، نه آنچه پیش‌تر کلون شده.

**اگر این فایل‌ها گم شوند، هیچ‌وقت نمی‌شود نسخهٔ تازه‌ای داد که روی نصبِ کاربرها بنشیند** — کلید
و رمزش را جای امن (و بیرون از هر مخزنی) نگه دارید.
