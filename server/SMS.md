# وصل کردن سرویس پیامک

کد ورود از **سرور** فرستاده می‌شود، نه از برنامه. برنامه‌ی روی گوشی
هیچ‌وقت با سرویس پیامک حرف نمی‌زند و کلید سرویس هرگز داخل فایل برنامه
نمی‌رود — اگر می‌رفت، هر کسی که APK را باز می‌کرد می‌توانست با اعتبار
شما پیامک بفرستد.

پس **در برنامه هیچ چیزی عوض نمی‌شود.** همه‌ی کار در `.env` سرور است.

## EasySendSMS — آماده، فقط کلید را بگذارید

اگر حساب EasySendSMS دارید (همانی که پنلش `my.easysendsms.app` است)،
این‌ها را عیناً در `.env` بگذارید:

```env
OTP_PROVIDER=sms

SMS_API_URL=https://restapi.easysendsms.app/v1/rest/sms/send
SMS_API_METHOD=POST
SMS_API_KEY=کلیدی-که-از-پنل-گرفتید
SMS_SENDER=Tohid

SMS_API_HEADERS={"apikey":"{key}","Accept":"application/json"}
SMS_API_BODY={"from":"{sender}","to":"{to_plain}","text":"{message}","type":"1"}
```

سه نکته که اگر ندانید وقت می‌برد:

**۱) `type` باید `1` باشد، نه `0`.** صفر یعنی متن انگلیسیِ ساده؛ با آن
متن فارسی و دری به هم می‌ریزد. یک یعنی یونیکد.

**۲) کلید در سرآیندِ `apikey` می‌رود**، نه `Authorization`. کلید را از
پنل، بخش تنظیماتِ API برمی‌دارید.

**۳) `{to_plain}` بنویسید، نه `{to}`.** سرور شماره را به شکلِ
`+93790000000` نگه می‌دارد و EasySendSMS آن `+` را قبول نمی‌کند.
`{to_plain}` همان شماره است بدون `+` و بدون فاصله: `93790000000`.
تبدیلِ `0790000000` به کدِ کشور را هم خودِ سرور انجام می‌دهد
(`DEFAULT_COUNTRY_CODE=+93`).

### حسابِ آزمایشی

در تصویرِ پنل، `Account Type` روی `Free Trial` و کاربر `Unverified` بود.
با حسابِ تأییدنشده معمولاً فقط به شماره‌ی خودتان می‌شود پیامک فرستاد و
نامِ فرستنده هم محدود است. اگر تست به شماره‌ی خودتان می‌رود ولی به
دیگران نه، مشکل از کد نیست — حساب باید تأیید و شارژ شود.

نامِ فرستنده (`SMS_SENDER`) هم باید در پنل ثبت و تأیید شده باشد، وگرنه
سرویس رد می‌کند. اگر ثبت نکرده‌اید، از پشتیبانیِ همان‌جا بپرسید چه
نامی مجاز است.

## چه چیزی از پنل سرویس لازم است

هر سرویس پیامکی شکل درخواست خودش را دارد. از بخش «مستندات API» یا
«وب‌سرویس» پنل، این چهار چیز را بردارید:

۱. **آدرس ارسال** — چیزی مثل `https://.../sendsms`
۲. **روش** — `POST` یا `GET`
۳. **نام پارامترها** — سرویس شماره‌ی گیرنده را چه می‌نامد؟ `receptor`؟
   `to`؟ `mobile`؟ متن پیام را `message` یا `text`؟
۴. **کلید کجا می‌رود** — در سرآیند (`Authorization` یا `X-API-Key`)، یا
   داخل آدرس، یا داخل خود بدنه؟

اگر خط خدماتی (شماره‌ی فرستنده) هم دارید، آن را هم بردارید.

## تنظیم در `.env`

```env
OTP_PROVIDER=sms

SMS_API_URL=https://api.example.com/sendsms
SMS_API_METHOD=POST
SMS_API_KEY=کلیدی-که-از-پنل-گرفتید
SMS_SENDER=شماره-خط-خدماتی
```

بعد شکل درخواست را می‌گویید. در آدرس، سرآیندها و بدنه، این‌ها جایگزین
می‌شوند:

| جاگذاری | چه می‌شود |
|---|---|
| `{to}` | شماره‌ی گیرنده، با `+` — مثل `+93790000000` |
| `{to_plain}` | همان شماره بدون `+` — مثل `93790000000` |
| `{code}` | کد شش‌رقمی |
| `{message}` | متن کامل پیام |
| `{sender}` | همان `SMS_SENDER` |
| `{key}` | همان `SMS_API_KEY` |

### اگر کلید در سرآیند می‌رود

```env
SMS_API_HEADERS={"Authorization":"Bearer {key}"}
SMS_API_BODY={"receptor":"{to}","sender":"{sender}","message":"{message}"}
```

### اگر کلید داخل آدرس است

```env
SMS_API_METHOD=GET
SMS_API_URL=https://api.example.com/v1/{key}/sms/send.json
SMS_API_BODY=receptor={to}&sender={sender}&message={message}
```

### اگر کلید داخل بدنه است

```env
SMS_API_BODY={"apikey":"{key}","to":"{to}","from":"{sender}","text":"{message}"}
```

نام‌های بالا نمونه‌اند. **نام واقعی را از مستندات سرویس خودتان
بردارید** — اگر سرویس `mobile` می‌خواهد و شما `receptor` بفرستید،
پاسخ خطا می‌دهد.

### اگر سرویس «قالب تأییدشده» می‌خواهد

بعضی سرویس‌ها متن آزاد را برای کد ورود قبول نمی‌کنند و باید یک قالب
ثبت کنید. آن قالب را این‌طور بگذارید:

```env
SMS_TEMPLATE=کد ورود توحید: {code}
```

## آزمایش، پیش از اینکه به کاربر برسد

```bash
cd server
node scripts/send-test-sms.js 0790000000
```

شماره‌ی خودتان را بگذارید. این دستور می‌گوید چه چیزی به سرویس فرستاده
شد و چه پاسخی آمد — و اگر نرفت، دلیلش را می‌گوید. تا این کار نکند،
ورود با شماره روی گوشی هم کار نمی‌کند.

## وقتی کار نکرد

| پاسخ سرویس | معمولاً یعنی |
|---|---|
| `401` یا `403` | کلید غلط است یا جای درستی فرستاده نشده |
| `400` با پیام درباره‌ی پارامتر | نام پارامترها با آنچه سرویس می‌خواهد نمی‌خواند |
| خطا درباره‌ی sender یا خط | خط خدماتی به این حساب تعلق ندارد |
| پاسخ ۲۰۰ ولی پیامک نمی‌رسد | معمولاً اعتبار تمام شده یا قالب تأیید نشده |

پاسخ خام سرویس در خروجی همان دستور بالا چاپ می‌شود؛ از روی آن معلوم
می‌شود کدام است.

## چند چیز که خود سرور می‌کند

اینها را لازم نیست شما تنظیم کنید:

- **کد خام هیچ‌جا ذخیره نمی‌شود** — فقط HMAC آن با راز سرور
- **مهلت** پنج دقیقه (`OTP_TTL_MIN`)
- **سقف تلاش** پنج بار، بعدش کد می‌میرد (`OTP_MAX_ATTEMPTS`)
- **فاصله‌ی ارسال دوباره** یک دقیقه (`OTP_RESEND_SECONDS`)
- **سقف روزانه** برای هر شماره، بیست بار (`OTP_DAILY_MAX`)

آخری مهم است: بدون آن، کسی می‌توانست با درخواست پشت سر هم اعتبار
پیامک شما را خالی کند.

## ایمیل و واتساپ

همین منطق برای آنها هم هست:

```env
OTP_EMAIL_PROVIDER=email
EMAIL_API_URL=...
EMAIL_API_KEY=...
EMAIL_FROM=...
```

سرور از روی خود نشانی تصمیم می‌گیرد: چیزی که `@` دارد با ایمیل می‌رود،
بقیه با پیامک یا واتساپ.

واتساپ فقط با API رسمی Meta کار می‌کند و حساب WhatsApp Business
می‌خواهد — از شماره‌ی واتساپ شخصی نمی‌شود کد فرستاد.
