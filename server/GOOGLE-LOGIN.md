# ورود با گوگل — راه‌اندازی روی سرور

همه‌ی کدِ لازم نوشته شده است؛ آنچه مانده فقط چند تنظیم در حسابِ گوگل و
یک متغیر در `.env` است. تا وقتی این متغیر خالی باشد، دکمه‌ی «ورود با
حساب گوگل» اصلاً در برنامه نشان داده نمی‌شود و هیچ‌چیز نمی‌شکند.

## اول: چه چیزی به چه چیزی وصل است

برنامه‌ی روی گوشی از خودِ اندروید یک **توکنِ امضاشده‌ی گوگل** می‌گیرد و
همان را دست‌نخورده به سرورِ شما می‌دهد. سرور امضای آن را با کلیدهای
عمومی گوگل می‌سنجد. پس:

- هیچ رازِ گوگلی داخلِ فایلِ برنامه نیست که با باز کردنِ APK لو برود
- شناسه‌ی کلاینت هم داخلِ برنامه نوشته نشده؛ برنامه آن را از
  `GET /api/v1/config` همین سرور می‌خواند
- هر کسی سرورِ خودش را دارد، با حسابِ گوگلِ خودش کار می‌کند

گوگل برای این کار **دو** کلاینت می‌خواهد که هر دو لازم‌اند:

| کلاینت | برای چه | کجا نوشته می‌شود |
|---|---|---|
| **Android** | تا گوگل روی گوشی قبول کند این برنامه خودش است | جایی نوشته نمی‌شود؛ فقط باید در گوگل ساخته شود |
| **Web application** | همانی که در توکن به‌عنوان مقصد می‌آید | `GOOGLE_CLIENT_ID` در `.env` |

نکته‌ای که همه را گیر می‌اندازد: چیزی که در `.env` می‌گذارید **کلاینتِ
Web است، نه Android**. توکنی که گوشی می‌دهد روی نامِ کلاینتِ Web صادر
می‌شود. اگر شناسه‌ی Android را بگذارید، سرور خطای
`این توکن برای برنامه‌ی دیگری صادر شده است` می‌دهد.

## گام ۱ — پروژه و صفحه‌ی رضایت

در <https://console.cloud.google.com> یک پروژه بسازید (یا یکی از
پروژه‌های موجود را انتخاب کنید).

بعد `APIs & Services ← OAuth consent screen`:

- نوعِ **External** را بزنید
- نامِ برنامه: `توحید` (همانی که کاربر موقعِ ورود می‌بیند)
- ایمیلِ پشتیبانی و ایمیلِ توسعه‌دهنده را پر کنید
- در `Scopes` چیزی اضافه نکنید؛ `email` و `profile` خودشان هستند

تا وقتی برنامه در حالتِ `Testing` است، فقط حساب‌هایی که در
`Test users` اضافه کرده‌اید می‌توانند وارد شوند. برای بازِ عمومی، دکمه‌ی
`Publish app` را بزنید — برای این سطح از دسترسی، بررسیِ گوگل لازم نیست.

## گام ۲ — کلاینتِ Android

`APIs & Services ← Credentials ← Create Credentials ← OAuth client ID`،
نوع: **Android**

| فیلد | مقدار |
|---|---|
| Package name | `ir.vil3ntec.tohid` |
| SHA-1 certificate fingerprint | `29:36:A0:E2:69:4E:89:47:A4:AB:AA:D5:3F:73:74:55:EB:EC:BB:CA` |

این SHA-1 مالِ همان کلیدی است که نسخه‌های منتشرشده با آن امضا می‌شوند
(`android-native/app/tohid-release.jks`). اگر روزی کلیدِ امضا را عوض
کردید، این را هم باید عوض کنید — وگرنه ورود با گوگل روی نسخه‌های تازه
کار نمی‌کند. برای گرفتنِ دوباره‌اش:

```bash
keytool -list -v -keystore android-native/app/tohid-release.jks -alias tohid | grep SHA1
```

اگر می‌خواهید نسخه‌ی `debug` هم روی رایانه‌ی خودتان کار کند، یک کلاینتِ
Android دیگر با همین نامِ بسته و SHA-1 کلیدِ debug بسازید:

```bash
keytool -list -v -keystore ~/.android/debug.keystore -alias androiddebugkey \
        -storepass android -keypass android | grep SHA1
```

## گام ۳ — کلاینتِ Web

باز هم `Create Credentials ← OAuth client ID`، این بار نوع
**Web application**. نامش هر چیزی باشد (مثلاً `Tohid Server`) و لازم
نیست `Authorized redirect URIs` را پر کنید — ما از آن جریان استفاده
نمی‌کنیم.

شناسه‌ای که می‌دهد چیزی شبیه این است:

```
123456789012-abcdefghijklmnop.apps.googleusercontent.com
```

همین را نگه دارید.

## گام ۴ — گذاشتن روی سرور

در `server/.env`:

```env
GOOGLE_CLIENT_ID=123456789012-abcdefghijklmnop.apps.googleusercontent.com
```

اگر بیش از یکی دارید (مثلاً کلاینتِ Web قدیمی و تازه در دوره‌ی گذار)،
با کاما جدا کنید؛ سرور همه را قبول می‌کند ولی به برنامه فقط اولی را
می‌گوید.

بعد سرور را بالا بیاورید:

```bash
# با Docker
docker compose up -d --force-recreate app

# دستی
systemctl restart tohid-server     # یا هر جور که سرور را اجرا می‌کنید
```

## گام ۵ — سنجیدن

```bash
curl -s https://YOUR-SERVER/api/v1/config | grep -o '"googleClientId":"[^"]*"'
```

اگر شناسه را برگرداند، کار تمام است. حالا در برنامه، آدرسِ همین سرور را
که بگذارید، دکمه‌ی «ورود با حساب گوگل» زیرِ خطِ «یا» ظاهر می‌شود. اگر
خالی برگشت، `.env` خوانده نشده — سرور را دوباره راه بیندازید.

## وقتی کار نکرد

| چه می‌بینید | چرا | چه کنید |
|---|---|---|
| دکمه اصلاً نیست | سرور شناسه نمی‌دهد | `curl` بالا را بزنید؛ `.env` و راه‌اندازیِ دوباره |
| پنجره‌ی گوگل باز می‌شود و بی‌صدا بسته می‌شود | SHA-1 یا نامِ بسته در کلاینتِ Android نمی‌خواند | گام ۲ را با فینگرپرینتِ همان APK‌ای که نصب کرده‌اید بسنجید |
| «روی این گوشی حساب گوگلی ثبت نشده است» | در `Settings ← Accounts` گوشی حسابی نیست | یک حسابِ گوگل به گوشی اضافه کنید |
| «این توکن برای برنامه‌ی دیگری صادر شده است» | شناسه‌ی **Android** در `.env` گذاشته شده | شناسه‌ی **Web** را بگذارید (گام ۳) |
| «ورود با گوگل روی این سرور تنظیم نشده است» | `GOOGLE_CLIENT_ID` خالی است | گام ۴ |
| «سرویس‌های گوگل روی این گوشی در دسترس نیست» | گوشی Play Services ندارد | با شماره یا ایمیل وارد شوید؛ این یکی درست‌شدنی نیست |

## چیزی که با این کار عوض نمی‌شود

ورود با شماره و ایمیل سرِ جایشان می‌مانند و «ادامه بدون حساب» هم همان‌طور
کار می‌کند. ورود با گوگل فقط یک راهِ اضافه است، نه جایگزینِ چیزی.

اگر کاربری که با گوگل وارد می‌شود ایمیلِ تأییدشده‌اش با حسابِ قبلی‌اش
روی سرور یکی باشد، همان حساب باز می‌شود — حسابِ دومی ساخته نمی‌شود.
