# shop | برنامه اندروید

برنامه‌ی گوشی **دقیقاً همان چیزی است که در سایت می‌بینید** — همان
`index.html` و همان فایل‌های `license/`، `sounds/`، `icons/` و `fonts/`
که داخل بسته گذاشته می‌شوند و از داخل خود گوشی اجرا می‌شوند.

```
android/app/src/main/java/af/tohid/shop/MainActivity.kt   ← پوسته
        ↓  بارگذاری از داخل بسته (بدون اینترنت)
index.html + license/ + sounds/ + fonts/                  ← خود برنامه
```

پس ظاهر، رنگ، انیمیشن، محاسبات و همه‌ی رفتارها مو‌به‌مو یکی‌اند و دو
نسخه هرگز از هم جدا نمی‌افتند: هر تغییری در سایت، با ساخت بعدی خودبه‌خود
داخل برنامه هم هست.

## چه چیزی را پوسته اضافه می‌کند

| کار | چطور |
|---|---|
| اجرای آفلاین | همه‌ی فایل‌ها داخل بسته‌اند؛ هیچ چیزی از اینترنت گرفته نمی‌شود |
| اسکن بارکد | اجازه‌ی دوربین گوشی به صفحه داده می‌شود |
| عکس محصول | انتخاب از گالری (بدون دوربین) |
| گرفتن پشتیبان | فایل در پوشه‌ی Downloads گوشی ذخیره می‌شود |
| به‌روزرسانی | دکمه‌ی «بررسی نسخه‌ی تازه» در تنظیمات، APK تازه را از گیت‌هاب می‌گیرد |
| فونت | Vazirmatn داخل بسته است؛ بدون اینترنت هم متن‌ها همان‌اند |
| پشتیبان‌گیری اندروید | دفتر دکان در پشتیبان گوشی هم می‌رود |

نسخه‌ی بومی قبلی (Compose) در `android/native-ui-archive/` بایگانی شده و
دیگر ساخته نمی‌شود.

## اتصال به سرور

برنامه بدون سرور هم کامل کار می‌کند (همه‌چیز روی همان گوشی)، ولی برای
همگام‌سازی، شاگردها و اشتراک باید به سرور وصل شود. راه‌اندازی سرور در
`server/README.md` توضیح داده شده است.

آدرس سرور دو راه دارد:

۱) داخل برنامه: «حساب و دکان» ← آدرس سرور ← ذخیره و بررسی اتصال
۲) هنگام ساخت، به‌صورت پیش‌فرض:

```bash
./gradlew assembleRelease -PshopServerUrl=https://shop.example.com
# یا
SHOP_SERVER_URL=http://198.51.100.10:3000 ./gradlew assembleRelease
```

دامنه اجباری نیست؛ IP هم کار می‌کند. اگر سرور را از کامپیوتر خانگی به
VPS بردید، فقط همین آدرس عوض می‌شود — نه نسخه‌ی تازه لازم است و نه
اطلاعاتی از دست می‌رود.

### ورود با گوگل (اختیاری)

`GOOGLE_CLIENT_ID` را روی سرور بگذارید. برنامه خودش از سرور می‌پرسد و
اگر تنظیم شده باشد، دکمه‌ی «ورود با حساب گوگل» را نشان می‌دهد. لازم
نیست چیزی در کد برنامه عوض شود.

## ساخت

```bash
cd android
./gradlew assembleDebug      # خروجی: app/build/outputs/apk/debug/
./gradlew testDebugUnitTest  # تست‌ها
```

روی گیت‌هاب هم با هر push خودکار ساخته و تست می‌شود
(`.github/workflows/android.yml`).

## انتشار نسخه و به‌روزرسانی از گیت‌هاب

```bash
git tag v1.0.1
git push origin v1.0.1
```

گیت‌هاب APK را می‌سازد و در Releases می‌گذارد. برنامه‌ی نصب‌شده روی گوشی
آخرین Release را می‌بیند و به‌روزرسانی را پیشنهاد می‌دهد.

### امضای رسمی (یک بار)

بدون کلید رسمی، بیلد با امضای debug ادامه می‌دهد تا خط لوله نشکند — ولی
برای انتشار واقعی کلید لازم است، وگرنه کاربر نمی‌تواند نسخه‌ی بعدی را
روی نسخه‌ی قبلی نصب کند.

```bash
keytool -genkey -v -keystore tohid.keystore -alias tohid \
  -keyalg RSA -keysize 2048 -validity 10000
base64 -w0 tohid.keystore > keystore.b64
```

سپس در `Settings → Secrets and variables → Actions` این‌ها را بساز:

| Secret | مقدار |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | محتوای `keystore.b64` |
| `ANDROID_KEYSTORE_PASSWORD` | رمز keystore |
| `ANDROID_KEY_ALIAS` | `tohid` |
| `ANDROID_KEY_PASSWORD` | رمز کلید |

**فایل keystore را گم نکن.** بدون آن نمی‌توانی نسخه‌ی جدید منتشر کنی و
کاربران باید برنامه را پاک و از نو نصب کنند (یعنی داده‌شان می‌رود).

## اتصال از هر جای دنیا

سرور خانگی پشت مودم است و از بیرون دیده نمی‌شود. یکی از این راه‌ها لازم است:

**۱) Cloudflare Tunnel — پیشنهاد من**
رایگان، بدون port forward، پشت CGNAT هم کار می‌کند، و https واقعی می‌دهد:

```bash
cloudflared tunnel login
cloudflared tunnel create tohid
cloudflared tunnel route dns tohid shop.example.com
cloudflared tunnel run --url http://localhost:4700 tohid
```

بعد در برنامه آدرس `https://shop.example.com` را وارد کن.

**۲) DDNS + port forward**
پورت ۴۷۰۰ روی مودم به سرور forward شود و یک آدرس DDNS بگیری. ساده‌تر
ولی شکننده‌تر: اگر اینترنت خانه IP عمومی نداشته باشد (CGNAT) کار نمی‌کند.

**۳) VPS ارزان**
سرور را روی یک VPS بگذار. مطمئن‌ترین، ولی هزینه‌ی ماهانه دارد.

بدون یکی از این‌ها، همگام‌سازی فقط داخل شبکه‌ی خانه کار می‌کند.
